# Development Council Role Cards

These tool-neutral cards make the Development Council operational in single-agent, multi-agent, and human-agent harnesses. A runtime may map one card to a dedicated agent or let one actor execute several cards sequentially. Every invocation must name the role, input artifact IDs, baseline, output artifact, veto status, and next owner.

Use the smallest council that covers the risk. `Specification Owner`, `Verification Owner`, and responsible human UAT remain accountable roles; specialist advice does not replace their decisions.

Recommended flow:

`Spec Architect → Experience reviewers → Quality Architect → System Architect → Security Officer + Failure Skeptic → Specification Owner → QA Analyst → Execution Engineer → QA Automation + Verification Owner → Documentation/Operations → human UAT`
